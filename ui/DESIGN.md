# Design System: 有数 · Streamlit 表面记录

## Overview

本记录只描述 `app.py` 与 `ui/presentation.py` 已实现的 Streamlit 表面，补充根目录 `DESIGN.md`，不替代原有账本界面的设计规范。
采用 Operate 模式：依照用户明确要求直接实现，继承有数蓝白体系；本表面没有另行批准的效果图。控件与状态以 Streamlit 原生组件为主。

## Colors

蓝色强调主操作、选中标签及焦点；浅色页面与白色侧栏形成安静的工作区，细边框区分表单和数据。
成功、信息、警告与错误沿用原生语义提示，并同时显示状态文字与原因，避免仅凭颜色表达结论。

## Typography

沿用系统字体栈，不加载远程字体。指标使用等宽数字与固定指标字号，移动端主标题使用较小字号。
“最长水下期”的数值与“单位：有效净值观测日”分开呈现，单位允许独立换行。
正文、来源与原始依据允许断行；依据保留缩进，不产生宽于容器的长行。

## Layout

桌面由账户配置侧栏与主分析区组成，主区最大宽度为 1240px，上下留白为 2rem / 3rem。
640px 以下主区采用 4.5rem 顶部留白，给原生移动页头留出空间；左右留白 1rem，底部 2rem。
四个结果标签允许整项换行，标签文字可换行，保持当前位置可见；网格子项允许收缩。
扫描预览占满可用宽度，仅在仓位标签激活后创建 dataframe，避免隐藏标签的无效宽度。
四列均指定 64px 最小起始宽度，原生 dataframe 会随容器自动伸展；完整扫描使用固定表格布局的 HTML，并允许单元格换行。

## Elevation & Depth

界面以浅底、白色面与细边框建立层次；本表面未额外引入装饰投影或材质。

## Components

- 持仓输入、增删与保存、风险滑块、基金搜索、折叠依据、标签与下载沿用原生控件；标签持续显示，按钮与链接具有可见焦点。
- 持仓点击保存后生效，风险滑块即时保存；提示文字持续说明两者的生效方式。
- 数据不足明确显示“无法判定”，已完成扫描但不满足预算明确显示“无可行解”；二者均不把零边界展示为可行零仓位。
- 假设投入金额保存在会话中，切换标签后仍可用于试算与导出。导出按钮身份由分析快照与金额共同生成，下载旁显示归档金额。
- HTML 归档保留结果、配置、来源与同一金额的试算快照；预格式依据和表格均允许换行。
- 减少动态效果偏好下关闭 CSS 动画和过渡。

## Do's and Don'ts

- 保留净值截止日期、来源、数据不足原因、历史口径和风险预算说明。
- 修改窄屏布局时，检查页头净空、标签换行、单位换行以及扫描表宽度。
- 本次浏览器记录在 1440、390、320px 的四个结果标签中均未测到横向滚动；记录还覆盖持仓保存后的条件更新与试算导出，未记录页面错误。
- 验证依据为 `outputs/desktop/browser/results.json` 及同目录最终桌面、手机截图；该证据描述所测会话的界面与交互，不构成对引擎、数据真实性或未来风险的新认证。
